# Functional Requirements

1. 1:1 chat support
2. user can send/view messages
3. Support for media sharing(images)
4. If one is offline, then messages should be delivered once the user comes
back online
5. Suport Recent chats
6. Real time messaging


# Non-Functional Requirements

1. High scale - 50M DAU
2. High consistency is imp, Good availability is imp
- Actually both of them are important, but consistency can be given 
priority, like ordering of messages, a sent message should always be visible.
3. High reliability
4. Ordering of messages should be taken care of
5. More Write heavy
 ^5glzmuVX

# Back of the Envelope

DAU = 50M
Each person send 10 messages per day
Writes per day = 50M * 10
WPS = 50M*10/10^5 = 5*100* 10^6 / 10^5 = 5 * 10^3 = 5k WPS 
Peak load = 20x
20 * 5 * 1000 = 100*1000 = 10^5 WPS

Assuming a sent message is also read, so it will read exactly once, you dont
actually go and read the same message again and again

so basically 1:1 Write:Read ratio

but still if we consider 10 writes and 10 reads, load on DB will be more heavy for
10 writes so a WRITE HEAVY system. ^kYoZXHyA
