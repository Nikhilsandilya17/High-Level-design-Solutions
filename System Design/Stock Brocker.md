# Functional Requirements
1. User should be able to place an order on the platform
- Order can be of type BUY/SELL.
2. User can view the price history of a stock
3. User should be able to get the price changes in real time.

Good to have
1. User is able to setup alerts for the price changes
2. No double order placed


# Non functional Requirements
1. The order placing part should be highly consistent.
- It can happen that user is seeing stale prices, but it
should not happen like an order placed is lost, at the end 
its money
2. Viewing of stock prices should be highly available.
- Its fine if the price shown is 10 sec stale, but user should
see it.
3. Scalability (100M Total users)




# Back of the envelope 

100M total Users

DAU = 10% of 100M
10*100M/100 = 10M

Assuming a single user opens up a stock 10 times a day
and tries to make 20 operations (includes both read and write)

Viewing stock price = More read heavy
Buy and sell = Less read heavy

10M*10*20 = 2B

2B request per day

QPS = 2B/10^5 = 20 * 10^8/10^5 = 20 * 10^3 = 20k
QPS = consist of both read and write operations

Peak load = 5x = 5 * 2B = 10B ^EzRkAORW
