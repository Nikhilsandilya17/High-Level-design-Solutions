FCM/APN ^R3fU6CpM

1. ProductPrice table in our Database will receive the Price changes for each product very frequently, so as soon as a new value is written 
to ProductPrice table, a CDC will be sent to PriceChangeStream which will be Kakfa, and that price change stream will be consumed 
by PriceChangeWorkers
2. PriceChangeWorkers will be query the Redis, for the users mapping who have created alert for that product and now for each user we will 
get there price threshold from NotificationAlert Table or Redis, if it satisfies then a notification will be sent.
3. But here PriceChangeWorkers will be querying redis for each user stored against that productId {productId: userId1, user2...}
4. This is damn slow, so to optimise this we can make use of Redis Sorted Sets where we can insert {product, userId, threshold}
5. When a price change event comes to PriceChangeWorkers We can make use of ZRANGEBYSCORE to get all the users who has score/threshold
 above that currentPrice received. 
6. Basically getting all the user who have set the priceThreshold above the priceReceived. Ex- priceReceived is 150 so getting all the users
above 150 means that the threshold has been breached for those users, like users may have set threshold as 155, 160 and now the price is 150
so thats why all the users who have set the threshold above 150 are qualified to receive the notification. [ TC: O(logn) ]
7. Once the notification is delivered change the status to SENT in NotificationStatus Table so that we dont end up sending multiple 
notifications for price fluctuations around 150 (149 -> 150 -> 151 -> 150 -> 149) or we can keep a redis cache to track this notification sending 
status for that (userId, productId) combo. ^tsRRxlic
